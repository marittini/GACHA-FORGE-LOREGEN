# 가챠포지 캐릭터 자동생성 v1.4.1

Gacha Forge에서 사용할 등장인물 프로필을 만들고 Marinara 로어북에 등록하는 개인 확장입니다.

## 설치
기존 등장인물 제작실 v1.0.0/v1.1.0/v1.2.0/v1.3.0을 비활성화하거나 제거한 뒤 이 ZIP을 가져오세요. 저장 키는 유지하므로 초안·설정이 이어집니다. 기존 초안이 10개보다 많으면 최근 10개만 남습니다.

## 실행
플로팅 버튼과 도크 버튼을 제거했습니다. 로어북 목록 상단 또는 개별 로어북 편집 상단의 캐릭터 생성 아이콘으로 실행하세요. 개별 로어북에서 열면 이름이 유일할 때 그 로어북을 저장 대상으로 선택합니다.

## 사용 흐름
1. ‘만들기’에서 AI에게 맡기기 또는 직접 쓰기를 선택합니다.
2. AI를 사용할 때 텍스트 연결과 아이디어를 입력합니다. 원작 설정은 참고란에 제공하거나 웹검색 자료를 요청하세요. 웹검색 기본값은 사용 안 함입니다.
3. ‘다듬기’에서 이름·한 줄 소개·외형·성격·말투·배경·능력을 확인합니다. 관계와 이격 설명은 필요할 때만 작성합니다.
4. 항목별 AI 수정은 수정안을 먼저 보여 줍니다. 적용해야 내용이 바뀝니다.
5. ‘저장’에서 대상 로어북을 고르고 등록합니다. 기존 항목은 덮어쓰지 않습니다.
6. Gacha Forge 세계 생성 화면의 Cast Lorebook에서 이 로어북을 선택하세요. 실행 중인 세계에 즉시 캐릭터를 추가하는 기능은 아닙니다.

## v1.4.0: 검색 수집 지침 직접 편집
‘만들기 → 웹검색 사용 → 검색 수집 지침과 프리셋’을 펼칩니다.

- 프로필 작성 지침과 별도로 검색용 AI에 보내는 수집 지침을 직접 편집합니다.
- 이름을 붙여 별도의 검색 프리셋으로 저장·불러오기·삭제할 수 있습니다. 최대 30개입니다.
- ‘기본 검색 지침으로 되돌리기’를 지원합니다.
- 지침 수정·프리셋 불러오기·기본값 복원은 이전 검색 자료를 무효화합니다. 다음 생성 전에 다시 검색 자료를 요청합니다.
- 입력 비우기·등록 초기화 시 검색 지침과 프리셋은 유지합니다.

기본 검색 지침은 인물 소개/줄거리 요약 대신 다음 자료를 수집하도록 합니다.
1. 외형(최우선): 머리 색·길이·질감·스타일, 눈 색·모양, 피부색, 얼굴, 체형·키, 종족 특징, 흉터·문신, 복장·색상·장신구·대표 장비, 시기별 차이.
2. 성격: 가치관·판단·행동·감정 표현·강점과 약점.
3. 말투: 호칭·존대·문장 습관·어조·감정 변화와 대사 자료.
4. 배경: 출신·신분·핵심 과거·동기와 목표.
5. 능력: 고유 능력·작동 방식·한계.
6. 관계: 중요한 인물과의 관계.
7. 이격 설명: 기본 캐릭터와 요청된 시점·이격의 차이.

검색 결과 화면도 이 7개 항목별로 나눠 보여 줍니다. 각 사실의 출처 링크와 찾지 못한 세부 정보를 표시합니다. 외형 자료가 없으면 경고하며 추측으로 채우지 않도록 전달합니다. 항목 구분 없이 일반 요약만 반환하면 생성에 사용하지 않습니다.

출처와 항목별 JSON 규격은 앱이 고정하고, 무엇을 어떻게 수집할지는 사용자가 편집합니다. 검색 결과의 sections와 missing을 그대로 프로필 생성 모델에 전달하고, 구체적인 외형 특징을 모호한 요약으로 대체하지 않도록 지시합니다. 이 지시는 실제 모델이 모든 특징을 보존한다는 보장이 아니며 결과를 확인해야 합니다.

이전 v1.3의 요약 검색 결과는 새 수집 방식의 근거로 자동 재사용하지 않습니다. 기존 프로필 작성 지침·작성 프리셋·초안·테마 등은 유지합니다.

## 작성 중인 프로필 비우기
상단 ‘비우기’ 또는 편집 화면 하단 ‘작성 중인 프로필 비우기’를 누릅니다. 현재 후보·프로필·아이디어·참고 입력·검색어·검색 반환 자료를 초기화합니다. 보관함 초안과 이미 등록한 로어북 항목은 삭제하지 않습니다. AI 연결·테마·언어·생성 지침·프리셋·웹검색 사용 여부·검색용 연결·참고 사이트 설정은 유지합니다. 처리 중에는 비우기를 사용할 수 없습니다.

## 웹검색 사용 / 사용 안 함
‘만들기 → 공식 설정을 참고할까요?’에서 선택합니다. 기본값은 사용 안 함입니다.

### 사용
1. 검색용 AI를 선택합니다. 프로필 작성 AI와 별도로 선택할 수 있습니다.
2. 캐릭터 이름과 작품명 등 검색어를 입력합니다. 비우면 아이디어 또는 현재 캐릭터 이름을 사용합니다.
3. 공식 사이트만 참고하려면 ‘참고할 사이트’에 도메인을 입력합니다. 예: finalfantasyxiv.com. 여러 개는 쉼표로 구분합니다.
4. ‘웹검색 자료 찾아보기’를 누릅니다. 이 단계에서는 프로필을 만들지 않습니다.
5. 출처 링크·참고 사실·확인되지 않은 부분을 검토합니다.
6. ‘검토한 자료로 프로필 생성’을 누릅니다. 모델에 자료를 전달하며, 확인되지 않은 공식 설정을 추측으로 채우지 않도록 지시합니다.

검색용 연결은 다음만 지원합니다.
- Google Gemini API / Google Vertex: customParameters.tools=[{googleSearch:{}}]. 검색을 지원하는 Gemini 모델·계정이 필요합니다.
- OpenRouter: customParameters.plugins=[{id:web,engine:exa,max_results:5}]. Exa 검색 결과를 요청하며, 사이트 제한은 include_domains로 전달합니다. 현재 문서에 남아 있는 웹 플러그인 경로를 사용합니다. 검색 요금은 연결 서비스에서 추가될 수 있습니다.
- 일반 OpenAI·Anthropic·구독·임의 호환 API에 위 옵션을 무조건 넣지 않습니다. 별도의 Gemini/OpenRouter 검색용 연결을 선택할 수 있습니다.

검색 자료가 비었거나 JSON 형식·출처가 유효하지 않으면 프로필 생성으로 넘어가지 않습니다. 검색 조건이 바뀌면 다시 검색 자료를 요청해야 합니다. 외부 사이트 텍스트는 자료로만 취급하도록 지시합니다. 출처 링크는 HTTP(S)만 허용하고, 사실은 반환된 출처 URL과 연결된 항목만 사용합니다. 공식 사이트 제한은 Gemini에서는 모델에 지시하고 반환 결과를 도메인으로 거릅니다. OpenRouter에서는 검색 서비스의 도메인 제한도 사용합니다.

**중요한 검증 범위:** Marinara /api/generate/raw는 모델 텍스트만 반환하며 Google groundingMetadata나 OpenRouter citation annotations를 전달하지 않습니다. 따라서 이 확장은 실제 검색 도구 옵션을 전달하지만 검색 실행 여부·웹페이지 내용·출처의 진위를 독립 확인하지 못합니다. 보여 주는 출처와 사실은 검색 옵션을 사용한 모델이 반환한 자료이며, 공식 설정으로 검증 완료했다고 표시하지 않습니다. 링크를 직접 확인하세요. 환각을 완전히 차단하는 기능은 아닙니다.

### 사용 안 함
검색용 호출을 하지 않고 검색 반환 자료를 프로필에 포함하지 않습니다. Gemini에는 tools=[]를, OpenRouter에는 tools=[]/plugins=[]를 보내고 :online 접미사를 제거한 모델을 요청합니다. 다른 서비스의 모델 자체 검색 정책이나 서버의 대체 연결 사용까지 통제하는 기능은 아닙니다. 저장된 연결 설정 자체는 변경하지 않습니다.

## 생성 지침과 프리셋
‘만들기 → AI에게 맡기기 → 생성 지침과 프리셋’을 펼칩니다.
- 생성 지침을 수정하면 다음 프로필 생성부터 적용합니다.
- 원하는 서술 방식·분량·말투 정리 방식을 직접 지시할 수 있습니다.
- ‘기본 지침으로 되돌리기’로 기본값을 복원할 수 있습니다.
- 이름을 적고 ‘현재 지침을 프리셋으로 저장’을 눌러 보관합니다.
- 목록에서 골라 ‘선택한 지침 불러오기’ 또는 ‘선택한 프리셋 삭제’를 누릅니다.
- 같은 이름의 프리셋은 덮어쓰지 않습니다. 새 이름으로 저장하세요. 최대 30개입니다.
- 지침을 자유롭게 바꿔도 필수 프로필 항목과 JSON 출력 규격은 유지합니다.
- 프리셋과 초안은 이 브라우저에 저장합니다.

## 초안 보관함
- 최근 초안 최대 10개 보관.
- 각 초안의 ‘삭제’ 버튼으로 삭제.
- 삭제한 현재 초안이 창을 닫을 때 자동으로 다시 보관되지 않도록 처리.
- 삭제한 내용을 편집해 바꾸거나 직접 ‘초안 보관’을 누르면 새로 보관할 수 있습니다.
- 빈 양식은 초안 보관함에 넣지 않습니다.

## 등록 완료와 반영 지연
기존 확장은 등록 API를 직접 호출하면서 Marinara 화면의 TanStack Query 캐시를 갱신하지 않았습니다. 최신 Engine 로어북 목록에는 5분 staleTime이 지정되어 있어 서버 저장이 끝나도 열린 화면에 이전 목록이 남을 수 있습니다. 이는 소스에서 확인한 구조이며 사용자 서버의 실제 지연 시간은 측정하지 않았습니다.

이번 버전은:
- 등록 전 동일 이름/내용을 확인해 중복 등록을 방지합니다.
- 등록 후 서버 항목 목록을 다시 읽어 저장 여부를 확인합니다.
- 읽기 확인이 실패해도 POST가 반환한 저장 항목 전체가 일치하면 성공으로 판단합니다.
- 저장 결과를 확인한 경우에만 입력 내용을 초기화합니다.
- 화면 상태에 서버 저장 확인 소요 시간을 표시합니다. 이 값은 서버 저장 확인까지 걸린 시간이며, 화면 전체 반영 시간이나 실제 모델 생성 시간은 아닙니다.
- 현재 Engine의 React QueryClient를 찾을 수 있으면 확인한 항목 목록을 캐시에 반영하고 로어북 관련 활성 조회를 다시 요청합니다.
- Engine에 공개 캐시 갱신 API가 없어서 React provider 체인의 QueryClient를 선택적으로 탐지합니다. Fiber를 수정하지 않으며, 찾지 못하거나 갱신이 실패하면 등록 성공은 유지합니다.
- 자동 화면 갱신 경로를 사용할 수 없으면 만들기 탭의 ‘로어북 화면 새로고침’ 버튼을 제공합니다. 이 버튼은 사용자가 눌렀을 때만 페이지를 새로고침합니다.
- 전체 페이지 자동 새로고침이나 다른 미저장 편집 내용의 변경은 하지 않습니다.

## 입력 초기화 범위
등록 성공 후 캐릭터 아이디어·참고 자료·필수/금지 설정·이격 방향·후보/편집 내용·희귀도/역할/속성/별칭·AI 수정 지시·프리셋 이름 입력을 초기화합니다. 새 로어북 이름은 기본값으로 돌아갑니다.
AI 연결·선택 언어/후보 수·테마·생성 지침·프리셋·저장 대상 로어북은 유지합니다. 보관함 초안도 유지합니다. 등록 실패·저장 여부 미확인 시에는 입력을 지우지 않습니다.

## 기타
라이트·다크 전환을 유지합니다. 직접 쓰기 ↔ AI 생성 전환 시 작성 내용을 보존하며 AI가 현재 초안을 참고하도록 선택할 수 있습니다. 로어북 JSON 내보내기와 복사를 지원합니다.

사용 경로: /api/connections, /api/characters, /api/generate/raw, /api/lorebooks, /api/lorebooks/:id/entries.

말투(Speech)는 로어북 텍스트로 저장됩니다. Gacha Forge의 유닛·대사 생성 과정에서 얼마나 유지되는지는 모델과 해당 프롬프트에 따릅니다. 엔진 프롬프트를 변경하지 않습니다.
